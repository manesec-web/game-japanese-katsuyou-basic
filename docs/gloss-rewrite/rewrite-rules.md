# 變化形中文改寫規則（修訂 31／逐形詞義）

本文件是本次 `vol/lesson_*.json` 中文改寫的施工規則。它不是產品規格；產品規格見 `docs/spec.md`。

## 0. 為什麼改

原本每個動詞的 15 個 `form.chinese` 都複製字典形的同一個詞義（386 個詞義、5,790 個欄位全部相同）。因此 `違いません` 顯示「不同; 不對; 不是」、`違いました` 也顯示「不同; 不對; 不是」，初學者會把否定、過去、可能、使役等形誤以為同一個意思。

本次讓每一形的中文反映該形本身的語義。中文以繁體、自然、適合初學者為準；不寫日文文法術語當解釋。

## 2. 允許改動的欄位

只改每一個 form 物件裡的：

- `chinese`（必改）
- `note`（僅在明確誤導初學者、或與新 `chinese` 矛盾時校正）

其餘一律不動，且施工後要比對 baseline 逐欄位相等：

`vol`、`group`、`japanese`、`sentence`（含所有 `japanese`／`chinese`／`note`）、`error_usage`，以及 15 個 form 鍵與其順序、物件鍵順序、lesson 名稱、`vols` 順序、陣列長度。檔案維持 `JSON.stringify(obj, null, 2) + '\n'`，UTF-8、無 BOM、LF。

不改：例句中文翻譯、日文例句、UI、命令、引擎、設定、manifest 的演算法。對例句有疑問只記入疑義清單，不修改。

## 3. 十五形的語義骨架

`P` = 從 `dictionary-form.chinese` 取得的主要中文述語（取第一個 `;` 前的詞，去掉括號與其內容；見 §5 的覆寫表）。以下為**通用骨架**，不是逐字套用公式；每一形仍須對照該形的 3 組例句中文，寫成讀得通的一句。

| form | 語義 | 自然中文寫法（以 `P` 表示） |
|---|---|---|
| `dictionary-form` | 辭書形／非過去肯定、普通體 | `P`（保留原詞義，必要時補主語或受詞） |
| `masu-form` | 非過去肯定、禮貌體 | `P`（禮貌體不改变中文；可寫「會 P／要 P」當例句是未來） |
| `masu-form-negative` | 非過去否定、禮貌體 | `不 P／沒有 P`（依例句選「不」或「沒有」） |
| `masu-form-past` | 過去肯定、禮貌體 | `P 了／曾經 P／（當時）P` |
| `masu-form-past-negative` | 過去否定、禮貌體 | `（當時）沒有 P／沒有 P 過／不曾 P` |
| `nai-form` | 非過去否定、普通體 | `不 P／沒有 P` |
| `ta-form` | 過去肯定、普通體 | `P 了／（當時）P` |
| `nakatta-form` | 過去否定、普通體 | `（當時）沒有 P／沒 P` |
| `te-form` | て形：接續、並列、原因、狀態 | `P，而…／P 之後…／因為 P…`；不可只寫 `P` |
| `potential-form` | 可能／能力／條件允許 | `能 P／可以 P／P 得出來／會 P` |
| `volitional-form` | 意向：提議、決心；或讓步「〜うと／〜うが」 | `（我們）P 吧／就 P 吧／打算 P`；讓步句寫 `就算 P 也…／不管 P 都…` |
| `imperative-form` | 命令／指示 | `快 P！／（給我）P！／要 P！` |
| `conditional-form` | ば形條件 | `如果 P／P 的話，就…` |
| `passive-form` | 受身：直接被動、迷惑受身、尊敬語 | `被…P／遭到…P／（某人）先 P，讓…困擾`；尊敬語依 note 寫 `（尊敬的）P` |
| `causative-form` | 使役 | `讓／叫／使…P`；狀態動詞可寫 `使…變得 P` |

### 狀態動詞與自發動詞的例外

`違う`、`ある`、`わかる`、`いる`、`できる`、`要る`、`似合う`、`咲く`、`降る`、`やむ`、`変わる` 等無意志／狀態動詞，可能形、命令形、使役形、被動形常常不是字面上的「能／命令／讓／被」。此時以該形的**例句中文**為準，並在必要時校正 `note`。例如：

- `違いません` → `沒有不同；相同`
- `違って` → `（因為）不同，而…`
- `違おう` → 例句是讓步 `就算…不同也…`，不是「～吧」
- `違わせる` → `使…不同／讓…有所區別`，不是「讓人去不同」

### `error_usage: true` 的統一標示

全部 191 形使用同一句，不編造通順譯法，不把不存在的日語當成可用詞：

```
（非自然日語；僅供轉詞練習，無自然中文譯義）
```

`note` 維持「錯誤詞語，僅供轉詞練習：…」的說明（D2 一則用語統一）。UI 的雙刪除線、錯誤單詞標籤、`跳過錯誤的單詞` 行為都不改。

## 4. 每個動詞的施工順序

1. 讀該動詞 15 形的 `vol`／`japanese`／`sentence[].chinese`／`note`。
2. 決定 `P`（§5），並記錄狀態／無意志動詞、尊敬語、迷惑受身、讓步等特殊判斷。
3. 依 §3 逐形寫中文，**每一形都對照自己的例句**，不用同一句複製 15 次。
4. `error_usage` 形套用統一標示。
5. 只在明確誤導時改 `note`；改動記入該批疑義／校正清單。
6. 寫入後執行 `validate-gloss-rewrite.mjs --batch N`，確認只有 `chinese`／`note` 改變。

## 5. `P` 的取得與覆寫

`P` 取 `dictionary-form.chinese` 第一個分號前、去掉 `（…）`／`(...)`／`〔…〕` 後的詞。35 個動詞的括號內是必要語意（如 `抽（菸）`、`帶（某物）去`、`（雨、風）停`），須在 `docs/gloss-rewrite/overrides.json` 手寫 `P`，不可直接去掉括號造成「抽」「帶去」「停」這種空泛詞。其餘 351 個動詞由規則取得。

覆寫表同時容納：

- `predicate`: 該動詞的自然中文述語。
- `forms`: 特定 form 的手寫中文（例如狀態動詞的讓步、受身、可能形）。
- `noteFix`: 允許修改的 note（原文字串 → 新字串）。
- `doubt`: 記入疑義清單、該形先保留原 `chinese` 不併入最終版的條目。

## 6. 「覺得怪怪的」處理

依使用者指示：

- 單條怪異（某形不自然、note 與新詞義矛盾、疑似該標 `error_usage`）→ 記入該批疑義清單、跳過該條、繼續其他條目；每批結束一次提出，確認後才併入最終版本。**不改 `error_usage`**。
- 會動到整體改寫規則（例如發現多數 `volitional-form` 其實都是讓步句、或 `passive-form` 大規模是尊敬語）→ 立即停下詢問。
- 例句有疑問 → 只記清單，不改例句。

## 7. 驗證契約

`scripts/validate-gloss-rewrite.mjs`：

- 50 個 lesson 都存在、可解析、canonical round-trip 一致。
- 15 個 form 鍵與順序、每個 form 的鍵集合與順序、lesson／`vols` 結構不變。
- 與 baseline 比對：除 `chinese`／`note` 外所有值（含 `sentence` 全部內容、`error_usage`、`vol`、`japanese`、`group`）逐項相等。
- 每個 `chinese` 是非空繁中字串；非 `error_usage` 形不得再與 `dictionary-form.chinese` 完全相同（除少數經 `overrides.json` 明示允許者）；不得殘留舊的「全部 15 形同義」狀態。
- `error_usage` 形全部等於 §3 的統一標示。
- 5,599 個可用形的例句仍包含自身 `vol`（標色功能）。
- `--batch N` 只檢查第 `10N-9`～`10N` 課，`--all` 檢查全部；`--check-invariants` 可在施工前驗證 baseline 自身。

最終另跑 `node scripts/write-sha256.mjs`（重寫 manifest）、`--check`、`npm test`、`npm run build`。
